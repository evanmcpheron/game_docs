Strong types without type proliferation

Use a cohesive struct for related inputs/results with named fields and explicit units. Small scalars and enums need no request object. When confusing two same-representation IDs has caused real errors, a narrow native wrapper can help; first verify its UHT/Blueprint/serialization fit. Do not build a generic ID framework preemptively.

Use Unreal fixed-width numeric types for stable data formats, TArray/TMap/TSet for project containers, FName for the existing internal authored ID vocabulary, FGuid for owned/placed identity where established, FString for processing text, and FText for localized display text. These are project API conventions following Epic naming and portable types. An identifier must be validated against the catalog, not merely be nonempty.

Keep reflected struct fields reachable through UPROPERTY where required; a USTRUCT declaration alone does not make every member reflected or GC-tracked. A value packet can expose editable fields when it is authored configuration, but runtime authoritative collections remain private on their owner. Do not return a mutable container reference to widgets or unrelated systems.

Separate the three item identities

  • ItemId: stable authored definition key resolved through GameCatalog.
  • EntryId: identity of a specific owned inventory entry; generated once on creation and preserved by saving.
  • PersistentId: identity of the placed pickup or other world source; authored and unique under its documented area scope.

Equipment maps Head/Body to owned EntryIds. It does not store another owned item copy. Reject removal of an equipped entry under the baseline policy. Never use an Actor name, memory address, display label or current array position as persistent identity.

One authoritative calculation

Stats rebuilds a complete final cache from base values, cumulative level growth and current equipment/passive/effect modifiers. Preserve the documented evaluation order: clamp ((base + cumulative growth + sum of flat modifiers) × (1 + sum of additive percentage fractions)). Define each stat’s clamp once. Do not increment an already-final cache for every event.

Source IDs such as Equipment:EntryId or Effect:Handle support diagnostics and duplicate detection; they do not justify a universal modifier manager. Profile supplies persistent build inputs; the body adds Effects and passes the complete inputs to Stats. Maximum health belongs to Stats, current health to Health. Capacity increases do not heal; decreases clamp current health. Platforming parameters are not automatically scaled by RPG levels.

Validate authored and imported data

Validate definition IDs, duplicate keys, finite numbers, durations, stack limits, equipment slots, graph prerequisites/exclusions and progression thresholds before activation. Metadata clamps assist editing but cannot enforce runtime correctness. Imported saves and stale widgets must pass the same domain validation as direct calls. A definition lookup failure returns an explicit failure without partial mutation; loading assets is outside the synchronous commit.

A new content category may warrant an enum only when the category is actually closed. SkillId, AbilityId, AreaId, NPCId and capability vocabulary remain authored identifiers or the existing tags; do not add giant enums listing every content instance.
