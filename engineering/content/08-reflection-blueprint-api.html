Deliberate exposure

Rule: every reflected or Blueprint-facing member needs a consumer or engine purpose. Why: exposure creates a maintained contract and mutable access can bypass invariants. Applies: new and modified UPROPERTY/UFUNCTION/UCLASS declarations. Exception: a GC-tracked reference needs UPROPERTY even without editor/Blueprint access. Reflection is not synonymous with public gameplay API.

Configuration is different from mutable state

UPROPERTY(EditAnywhere, BlueprintReadWrite)
float CurrentHealth;

UPROPERTY(EditAnywhere, BlueprintReadWrite)
TArray<FInventoryEntry> InventoryEntries;

Avoid these declarations on authoritative owners. Prefer private storage and narrow commands:

// HealthComponent.h fragments
public:
    UFUNCTION(BlueprintPure, Category = "Health")
    float GetCurrentHealth() const;

    UFUNCTION(BlueprintCallable, Category = "Health")
    bool RestoreHealth(float Amount);

private:
    UPROPERTY(VisibleInstanceOnly, Transient, Category = "Health")
    float CurrentHealth = 0.0f;

// PlayerCharacter.h configuration fragment
private:
    UPROPERTY(EditDefaultsOnly, Category = "Movement|Jump",
        meta = (ClampMin = "0.0", Units = "s"))
    float JumpBufferWindow = 0.10f;

RestoreHealth validates finite positive input, readiness and recovery/death policy in .cpp. The example return means an accepted health change; dead-body recovery remains explicit. JumpBufferWindow is the documented starting test value, not final tuning. Editor metadata is not runtime validation.

Queries have no hidden mutations

BlueprintPure is reserved for cheap side-effect-free queries. Do not perform loading, saving, cache mutation, random choices or hidden expensive reconstruction in a pure node. Pure calls can be reevaluated; an inventory view that copies a collection or computes a build may need an explicit execution-pin query with BlueprintPure=false. Const does not justify hidden mutable state or imply cheapness. Engine behavior: Epic UFunctions.

Return view/snapshot values that cannot mutate the authoritative store. A BlueprintReadOnly UObject reference still allows callable methods on that object; enforce invariants there. Avoid exposing native-only internal commit helpers with BlueprintCallable or using AllowPrivateAccess to make every field convenient.

Names, outputs and compatibility

Give nodes domain categories, explicit names and a consistent result meaning. A bool is sufficient for one clear accepted/rejected condition. Use an enum/result struct when callers need several actionable failure causes. Initialize all outputs on failure; document whether zero change is accepted, which notifications fire and whether success means committed or merely queued.

Keep presentation hooks bounded. BlueprintNativeEvent overrides go in _Implementation in .cpp; normal calls go through the reflected event wrapper. Do not apply Server/Client/NetMulticast or introduce replication simply because UE supports them; multiplayer is not established by this task. Rename reflected APIs through a scoped compatibility plan with deprecation/redirects and consumer validation, not a formatting sweep.
