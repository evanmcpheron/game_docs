Use events where they reduce real coupling

Rule: owners publish completed changes to optional observers. Why: Health should not depend on every UI, animation, body reaction or audio system. Applies: health/death, profile commits, equipment/build updates, progression, interaction selection, checkpoints and save completion. Exception: a direct call is clearer for an owned dependency or required orchestration. Do not introduce a global event bus to avoid simple references.

Use native delegates for native-only listeners. Use dynamic multicast delegates and BlueprintAssignable only when Blueprint subscribers need them. A dynamic handler requires an appropriate UFUNCTION signature. Native UObject-aware bindings such as AddUObject or weak lambda bindings are preferable to unguarded raw captures of UObjects. Delegate mechanics: Epic dynamic delegates.

A producer does not know its observers

// HealthComponent.h fragments
DECLARE_DYNAMIC_MULTICAST_DELEGATE_TwoParams(
    FHealthChanged, float, PreviousHealth, float, CurrentHealth);

public:
    UPROPERTY(BlueprintAssignable, Category = "Health")
    FHealthChanged OnHealthChanged;

private:
    void PublishHealthChange(float PreviousHealth);
// HealthComponent.cpp
void UHealthComponent::PublishHealthChange(float PreviousHealth)
{
    if (PreviousHealth == CurrentHealth)
    {
        return;
    }

    OnHealthChanged.Broadcast(PreviousHealth, CurrentHealth);
}

This fragment publishes an already committed scalar change. The mutation path first validates damage/restoration, clamps health and establishes lethal/once-only guards. It must also hold its mutation/publication guard and respect cross-owner deferred notification. The helper does not save, award XP or start recovery. Body adapters own those reactions. The simplified example omits the complete damage/result/death contract.

Callbacks are an external boundary

Commit all observable state before broadcasting. A listener may query the owner, submit another command or destroy an Actor. Define whether reentrant writes are rejected or scheduled after publication; the existing cross-model plan rejects them. Never depend on delegate subscriber order. A required stat rebuild or transaction half belongs in explicit orchestration before public notification, not an optional HUD listener.

Publish only the necessary domain facts. A bulk inventory/equipment/skill operation should have a coherent notification set and one profile/persistent revision, not one save per entry. Avoid cycles where OnStatsChanged directly causes another identical rebuild. An event should name a fact, such as OnEquipmentChanged, rather than an ambiguous instruction such as ProcessEquipment.

Subscriptions have owners and teardown

  1. Resolve the current source and validate readiness.
  2. Remove this listener’s previous subscription before rebinding.
  3. Bind once, then pull the current snapshot/readiness state so late listeners cannot miss initialization.
  4. Keep native FDelegateHandle values where the API returns them; remove precisely that binding. Dynamic bindings use matching AddDynamic/RemoveDynamic or an intentionally unique binding.
  5. On source replacement, unpossession, widget teardown or EndPlay, unbind and clear old references. Avoid RemoveAll/broad clear operations that erase unrelated listeners.

UObject-aware bindings help avoid calls on dead receivers, but do not replace semantic unbinding or prevent duplicate subscriptions after repeated setup. A raw C++ listener must outlive its binding or remove it. Widgets can be reconstructed several times; choose the actual controller/widget setup and teardown paths and verify repeated open/close behavior.

Delayed completion carries identity

Capture a value token and a weak live-object reference for callbacks that outlive the current stack. Validate reference, readiness and execution generation at delivery. Saves also need snapshot revision and session identity. A valid object may now be executing a different attack or representing a new session, so IsValid alone cannot reject stale work.
