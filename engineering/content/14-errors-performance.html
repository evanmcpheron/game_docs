check expressions may not execute in shipping configurations; verify evaluates its expression when checks are disabled; ensure reports a nonfatal condition but needs explicit subsequent control flow. Do not put essential gameplay mutation inside assertions. See Epic asserts.

if (!ensureMsgf(IsValid(StatsComponent), TEXT("Health requires initialized Stats")))

if (!FMath::IsFinite(Amount) || Amount <= 0.0f)
{
    return false;
}

This validation fragment separates an unexpected required dependency from an invalid public numeric request. Additional readiness/death/maximum rules remain in the owner. Validate NaN/infinity, integer overflow and bounded counts before arithmetic or staged mutation. Guard array access and imported enum values; a default switch must not accidentally authorize an unknown state.

Tick is an intentional scheduling choice

Rule: disable Actor/component Tick by default and enable it only for a demonstrated continuous behavior. Why: hidden polling scatters rules and wastes work. Applies: all new classes. Exception: movement observation/input integration, active combat spatial queries, shared visual clocks and other genuinely frame-dependent work. Native Character Movement already ticks; disabling a custom Actor Tick does not remove the engine’s movement integration.

// PersistentStateComponent constructor fragment
PrimaryComponentTick.bCanEverTick = false;

Inventory, equipment, skills, Profile/WorldState and SaveGame do not need continuous polling. Stats rebuilds on complete input changes. Use input/collision events, completed-change delegates, timers and explicit transitions when they express the requirement.

When Tick’s reason is non-obvious, document what it evaluates, why events/timers are insufficient, when it is enabled, its clock and ordering. Active combat may disable its update when idle; an ability recharge ledger stops updating when full; effects stop their timer when empty. Do not add a second update path executing the same operation from both input and Tick.

Timers and clocks are domain policy

Timers suit bounded AI decisions, effect expiry and deadline-based recharge, not per-frame movement impulses. Keep FTimerHandle values, clear owned timers on teardown and validate weak targets/execution identity in delayed work. A callback’s time is not guaranteed to match an exact render frame; advance bounded elapsed/deadline logic correctly after hitches. Timer mechanics: Epic gameplay timers.

Gameplay effects/recharge use the project’s pause-respecting game clock. UI can animate cosmetic progress independently; it cannot restore charges. Save retry/completion while paused cannot assume a gameplay timer advances. Normal-travel handoffs contain remaining duration instead of old absolute world timestamps.

Correctness before optimization

Do not introduce pooling, caching layers, custom allocators, parallel gameplay or complex data structures without evidence. Start with straightforward domain code. Avoid known meaningful costs: repeated whole-world scans, synchronous asset loads during action acceptance, copying large views in pure Blueprint nodes, redundant rebuilds and allocations in hot updates.

When optimizing, record the measured workload, profiler/build/platform, observed cost and result. Preserve public behavior, deterministic rule inputs, ownership and save compatibility. A cache needs an authoritative source, explicit invalidation and a reconstruction proof. Test representative hitches and low-frame-rate combat geometry; a faster update that misses the active interval is incorrect.
