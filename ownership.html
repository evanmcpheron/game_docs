Where does this state live?

The source ownership matrix, with explicit cache, snapshot and handoff boundaries.

Native types, not new owners

UGameInstance ↗ · UObject ↗ · USaveGame ↗

Profile and WorldState remain plain project Objects; SaveGame remains a snapshot. Project-specific C++ index.

A cached value, handoff and serialized snapshot can reflect a fact without becoming another independent authority. Ask who is allowed to change the value, then have other systems query or request that owner. The table follows current ownership, including the PaperZD presentation decision.

Body animation observes gameplay; BPC_EquipmentVisuals only synchronizes wearable render layers. Profile retains equipped-entry ownership. Neither owns damage, movement permissions, cooldowns or cancellation.

Boundary examples

Current health belongs to Health; capacity belongs to Stats. Equipment slots point to Profile-owned EntryIds. WorldState keeps opened passages and discovery while AreaRoot keeps the current room. A current dialogue cursor belongs to Controller, but remembered conversation facts belong to WorldState.

During handoff

Suspend mutation on the old body before GI captures its value handoff. GI temporarily holds those values while the new body is not ready. After reconstruction, the new components own runtime values and the handoff is cleared. This is a transfer of authority, not two bodies continuing to simulate the same player.

Use the reset-policy table for room traversal, area travel, death and disk load. Original matrix: Part AD.
