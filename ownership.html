Body animation observes gameplay; BPC_EquipmentVisuals only synchronizes wearable render layers. Profile retains equipped-entry ownership. Neither owns damage, movement permissions, cooldowns or cancellation.

Boundary examples

Current health belongs to Health; capacity belongs to Stats. Equipment slots point to Profile-owned EntryIds. WorldState keeps opened passages and discovery while AreaRoot keeps the current room. A current dialogue cursor belongs to Controller, but remembered conversation facts belong to WorldState.

During handoff

Suspend mutation on the old body before GI captures its value handoff. GI temporarily holds those values while the new body is not ready. After reconstruction, the new components own runtime values and the handoff is cleared. This is a transfer of authority, not two bodies continuing to simulate the same player.

Use the reset-policy table for room traversal, area travel, death and disk load. Original matrix: Part AD.

Mana/stamina ownership and approved scope

Approved architecture addition · 08 October 2026. One new production asset, BPC_Resources, is a Phase 2 Blueprint Actor Component (ActorComponent) in Content/Game/Combat/. Preserve every existing asset identity, phase and Content folder. This addition does not alter the historical original roadmap.

OwnerAuthoritative responsibilityExplicit exclusion
BP_PlayerProfilePersistent progression, purchased skill IDs/points, inventory/equipment decisionsNo current mana/stamina or duplicate class/bonus ledger
BPC_StatsComplete calculated seven-stat cache; final resource capacities and regeneration ratesNo current pools, resource spending or per-frame build reconstruction
BPC_ResourcesCurrent runtime mana/stamina, atomic spend/restore, game-time regeneration, clamp and suspensionNo purchases, inventory, abilities, levels, UI drawing or disk truth
BPC_HealthCurrent health, damage acceptance and deathNot merged with Resources
BPC_Combat / BPC_AbilitiesAction execution and matching token ownership; Phase 9 Abilities validates and commits resource costsNo direct resource-variable writes; basic attacks stay free
WBP_HUD / WBP_AbilitiesRead-only snapshot display and validated requests to ownersNo resource authority or per-frame stat recalculation
S_RuntimeTravelState / BP_SaveGameExisting in-memory handoff carries current pools; disk snapshot carries persistent build decisionsNo old body references; no current-resource fields in S_CharacterSave

Authored definitions describe balance, Profile holds session decisions, Stats is a derived cache, Resources is a replaceable body component, UMG is a view, disk save is a value snapshot, and normal travel is a separate in-memory runtime handoff. Do not introduce GAS, a generic attribute framework, separate Mana/Stamina components or a GameInstance resource manager. New/death/disk recovery is full; normal travel preserves and clamps absolute current values. Every valid build retains resource-free basic movement and attacks.
