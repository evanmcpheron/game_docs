Paper2D + PaperZD architecture decision

Current animation standard, retired custom infrastructure and compatibility boundary.

On this page

Decision and scope

Adopt Paper2D + PaperZD as the standard now. Paper2D remains the sprite/flipbook/tile rendering foundation; PaperZD owns complex character presentation. Gameplay owners, cancellation tokens, movement scope, persistent identity and all recovery policies remain unchanged. See the complete implementation contract.

Retired plan and replacements

Historical planned assetCurrent treatment
BPC_FlipbookAnimatorRetired. Native PaperZD graph/player controls body playback. Only clothing projection remains in BPC_EquipmentVisuals (Phase 7).
BPDA_AnimationSetRetired as body catalog. Native Animation Sources and sequences replace it. Wearable mapping becomes BPDA_EquipmentAppearance; no transitions/looping/clock fields.
E_AnimStateRetired. State nodes live in the PaperZD graph; no parallel enum with duplicate transitions.
S_AnimationSnapshotRetired as push/playback infrastructure. AnimInstance queries the existing gameplay owners and holds only a read-only observation cache.

DA_Anim_TestHelmetReplaced by DA_Equipment_TestHelmet using the smaller wearable schema.

The current register contains 164 assets: 149 historical entries minus six retired plans plus 20 animation/equipment additions (17 native PaperZD assets and three equipment contracts), plus the separately approved Phase 2 BPC_Resources addition. The resource addition does not change PaperZD ownership. There are still 20 Content folders, 12 phases and 19 system chapters. Phase counts are 8, 16, 25, 32, 9, 20, 3, 8, 8, 17, 16, 2. Current manifest drives indexes and dependency maps. Historical manifest and original roadmap remain byte-for-byte preserved.

Compatibility and migration in the real game

This checkout is documentation, not verified Unreal code/assets. No asset redirects or save migration have been executed. Inspect the actual project first. Enable and validate the installed plugin, reparent player/enemy Blueprints or their native bases deliberately, preserve their capsule/movement settings, component composition, interfaces and public gameplay contracts, assign AnimInstanceClass and remove the old body playback graphs/components in the same scoped migration.

Convert character definition BaseAppearance and enemy definition AnimationSet into AnimInstanceClass references to UPaperZDAnimInstance classes. Convert item Appearance to the new wearable schema and translate sequence mappings explicitly. Remove old enum/snapshot consumers after references are migrated. AnimInstance state is transient; inventory ItemId/EntryId/slots and saves retain their existing contracts. Even when no animation fields are saved, verify real Blueprint pins, serialized content references, defaults and retained fixtures before removing implemented types. Do not assume this documented rename automatically redirects Unreal assets.

Retain interruption/deadline/cancel cleanup in ActionState, Combat, Abilities and the body. Test missing/interrupting notifies and stale old-body callbacks. Native composite layers/skins are an implementation alternative only after the actual installed PaperZD release proves the required wardrobe mapping; remove any replaced manual writer.
