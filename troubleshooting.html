Start with the symptom, identify the state owner, then test the smallest correction. Do not add arbitrary Delay nodes or duplicate variables to conceal an initialization/ownership error.

Player does not spawn

DiagnosisWhat to inspect
Why it happensWrong map/GameMode override, duplicate spawn policy or unmet bootstrap prerequisites.
Correct ownerBP_GameMode owns spawning; GI owns session readiness.
Correct patternPhase 0: Default Pawn=BP_PlayerCharacter + native PlayerStart. Phase 3+: Default Pawn=None, registered AreaRoot/Controller/spawns, ready models/definitions, valid destination and successful Spawn Actor result before Possess.
How to test the fixPrint each readiness prerequisite and spawn count. Fix the first failed prerequisite; expect exactly one initialized body.

Player jumps twice

DiagnosisWhat to inspect
Why it happensNative Jump and custom Launch both fire, duplicate input routing or stale-ground budget reset.
Correct ownerBP_PlayerCharacter owns the single jump budget; native movement integrates the launch.
Correct patternRemove native Jump binding; one Started request, one budget consume before launch, no re-arm while bLaunchPending.
How to test the fixWalk off, coyote-jump once, press again before landing. Expect the second request rejected. Count OnJumpCommitted, not visual frames.

Buffered tap becomes a full-height jump

DiagnosisWhat to inspect
Why it happensRelease arrived before positive velocity or before the buffered request was consumed.
Correct ownerPlayerCharacter jump-cut state.
Correct patternRetain bPendingJumpCut or derive it from bJumpHeld at consumption; apply once after launch observation and only to positive Z.
How to test the fixPress/release just before landing and in one frame. Expect one short jump with bJumpCutConsumed once.

Pickup returns after loading

DiagnosisWhat to inspect
Why it happensUnstable/duplicated PersistentId, missing world record export or reward in restoration.
Correct ownerWorldState claim record and GI coherent transaction.
Correct patternVerify authored ID, Collected record, snapshot revision and ApplyPersistentRecord without TryAddItem.
How to test the fixCollect, restart and inspect both inventory quantity and world key. Applying the record twice must not grant again.

Equipment bonus keeps increasing

DiagnosisWhat to inspect
Why it happensModifiers appended to an old final result or saved final stats treated as permanent base.
Correct ownerStats complete-cache rebuild; Profile owns current slots.
Correct patternRebuild from definition + current owned slot/skill/effect inputs with source IDs. Do not repeatedly add the same equipment contribution.
How to test the fixEquip/unequip and import the same save ten times. Expected baseline remains unchanged when unequipped.

UI updates twice or reads an old Pawn

DiagnosisWhat to inspect
Why it happensDuplicate bindings or missing teardown/current-body reassignment.
Correct ownerPlayerController and each widget’s binding lifecycle.
Correct patternUnbind old source, assign new reference, bind once, pull snapshot. Remove exact long-lived model subscriptions on close/EndPlay.
How to test the fixThree respawns then one accepted hit should produce one active HUD update, not three.

Crossing an area heals the player

DiagnosisWhat to inspect
Why it happensNormalTravel accidentally used clean recovery initialization or handoff applied before final capacity was rebuilt.
Correct ownerGI entry reason and body handoff.
Correct patternKeep E_EntryReason explicit. Restore effects/build/maxhealth before current health; do not call RestoreForRecovery on normal travel.
How to test the fixTravel A→B at half health. Expect the same amount clamped to valid maximum, not a refill.

Latest progress disappears after an old save completes

DiagnosisWhat to inspect
Why it happensLastSavedRevision was set to current revision rather than captured InFlightRevision.
Correct ownerGI save queue.
Correct patternKeep immutable snapshot and captured revision; success marks only that revision and schedules a newer snapshot.
How to test the fixStart write at 12, commit 13, finish 12. Expect dirty revision 13 still pending until its own successful write.

Pause menu cannot close or travel hangs after save failure

DiagnosisWhat to inspect
Why it happensClose input route is paused/removed, a paused timer is awaited, or mandatory flush has no failure decision.
Correct ownerController focus/input mode and GI completion-driven I/O coordination.
Correct patternProve focused UMG or paused-enabled action route. Wait on real I/O completion; show Retry/acknowledged-unsaved choice rather than endless blocking.
How to test the fixPause while a write is pending, inject failure, then try cancel/retry. Expect visible feedback and a deliberate usable route.

An ability refills when changing equipment

DiagnosisWhat to inspect
Why it happensRefreshUnlocks reset a still-valid runtime ledger on each build notification.
Correct ownerBPC_Abilities charges/deadlines.
Correct patternReconcile new/removed unlocks while retaining existing still-unlocked cooldown state.
How to test the fixUse TestPulse, equip TestHelmet, inspect deadline. It must not reset to fully charged.

Project works in PIE but a packaged map or visual is missing

DiagnosisWhat to inspect
Why it happensMap/soft reference was not included/resolved by the actual cook.
Correct ownerCatalog/content authoring and packaging validation.
Correct patternInclude referenced slice maps/fixtures for the development build, then verify actual packaged ID lookup and presentation loading.
How to test the fixFully launch packaged executable from clean test data, traverse both areas and activate test executor; inspect load/cook errors.
