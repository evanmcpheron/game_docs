Phase 7 of 0–116 new assets

Goal and why this phase comes now

Prove: Prove equipment changes stats and appearance without copying ownership or compounding bonuses.

Equipment depends on stable inventory EntryIds and a stat cache that can be rebuilt rather than incremented.

Recommended asset-creation order

Create every listed asset in its exact folder. For classes/components, the first pass creates and compiles shells; fill cross-referencing variables/graphs after their types exist. This avoids a circular “create A before B before A” problem without changing the architecture. A data instance requires its compiled schema; a child Blueprint requires its compiled parent. Creating a shell does not implement later-phase mechanics.

  1. WBP_Equipment — Create with the exact parent/type, compile the shell and save; then implement its current-phase fields and functions.
  2. T_TestHelmet — Create/configure the native content asset and save before assigning it in the consuming definition/map.

  4. FB_Helmet_Test — Create/configure the native content asset and save before assigning it in the consuming definition/map.

Implementation sequence

01. Validate equipment ownership first

Implement TryEquip/TryUnequip on the existing Profile. Slots reference owned Guids; no second inventory. Use E_EquipmentSlot Head/Body already created as schema in Phase 3.

02. Create exact helmet fixtures

Create DA_Item_TestHelmet and DA_Anim_TestHelmet in Tests, import T_TestHelmet/create SPR_TestHelmet in Art and FB_Helmet_Test in Animation. Do not move them into Equipment just because of their purpose.

03. Assemble one build refresh

Resolve current equipped definitions and replace modifier input on each rebuild. Publish one OnBuildChanged after the slot change. Increasing maximum health does not refill current health.

04. Add synchronized native layers

Add EquipmentRoot, HeadLayer and BodyLayer inside BP_PlayerCharacter. Disable visual collision and initialize animator layer refs. Resolve appearance through definition references and immediately align to the shared clock.

05. Add screen and prove identity

Create WBP_Equipment with model queries/requests. Acquire two identical helmets, equip/replace/unequip/load and compare exact EntryIds and final stats. No bonus accumulation or ownership loss is acceptable.

Connections to wire in this phase

Equipment request → Profile mapping → OnBuildChanged → Stats and animator → UI/save update.

Read the APIs on each asset page for the caller, explicit inputs/outputs and allowed state changes. The linked system chapters give the end-to-end call flow: Equipment and visible layers, Animation and layered presentation, Stats and build reconstruction.

Prerequisites

Inventory identity, stat rebuilding, and base flipbook presentation.

Future typed dependencies shown on an asset reference page are staged extensions, not a requirement to implement later phases now.

Run the phase tests

Equip, replace, unequip, acquire two identical helmets, and reload. Verify no duplicated modifiers, invalid slot references, free healing, or disappearing ownership. Change equipment mid-jump/attack and confirm layers remain synchronized and non-colliding.

Stop condition

Equipment changes character stats and appearance through data, with one authoritative ownership record.

Do not move on with an unexplained failure

A checked box should mean you ran the test in your project. Website audit results are not Blueprint test results. Record the actual expected/observed value, current phase, engine build and relevant stable ID/token.

Do not build yet

Multiple loadouts, cosmetic overrides as a separate system, durability, item randomization.
