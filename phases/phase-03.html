Phase 3 of 0–1132 new assets

Goal and why this phase comes now

Prove: Prove lasting values survive Actor replacement during travel and death within one session.

In-memory truth must survive travel and recovery before disk serialization can be trusted to capture it.

Recommended asset-creation order

Create every listed asset in its exact folder. For classes/components, the first pass creates and compiles shells; fill cross-referencing variables/graphs after their types exist. This avoids a circular “create A before B before A” problem without changing the architecture. A data instance requires its compiled schema; a child Blueprint requires its compiled parent. Creating a shell does not implement later-phase mechanics.

Implementation sequence

01. Create leaf and composite value types

Create E_EquipmentSlot and E_EntryReason, then inventory/world/checkpoint/recovery leaf structs before S_CharacterSave, S_WorldSave and transition/handoff composites. Inventory/equipment fields are schema only; timed handoff fields wait for Phase 9.

02. Create Object models and catalog

Compile Profile/WorldState shells, area schema and GameCatalog schema. Fill only phase-available typed catalog maps. GI constructs the two Objects once with Outer self and explicit strong references, then initializes them synchronously.

03. Build interaction and persistent application

Create interface/component shells, then implement candidate queries and stable-ID adapter injection. Persistent Actors start unready; ApplyPersistentRecord updates projection only. Add guarded switch/target transactions before disk I/O exists.

04. Author two area maps

Create L_Slice_A/B and their area definition instances in Tests. Add exactly one AreaRoot per map, safe named spawns, room volumes and separate forward/reverse transitions. Register actual map refs and start destination in DA_GameCatalog.

05. Replace spawning

Set gameplay Default Pawn Class=None. Register root/controller/spawns and retry guarded bootstrap until ready. Initialize persistent Actors, spawn/init/possess one body and bind then pull UI. Do not supplement automatic spawning.

06. Implement distinct travel and recovery

Normal travel preserves current health through S_RuntimeTravelState. Checkpoint activation stores IDs; death retains current models and reloads checkpoint area for clean runtime recovery. Do not call Load Game from Slot.

07. Prove in-memory persistence

Open a shortcut, travel A→B→A, discover rooms repeatedly, activate checkpoint and die after another temporary test profile change. Model values stay while Actors are replaced. Missing/duplicate IDs/spawns must report useful failure.

Connections to wire in this phase

Interaction → target operations → GameInstance → WorldState. GameMode rebuilds Actors/body from models. Area transitions move value-based destination requests through GameInstance, not old Actor references.

Read the APIs on each asset page for the caller, explicit inputs/outputs and allowed state changes. The linked system chapters give the end-to-end call flow: Persistent models and stable world identity, Interaction, Areas, rooms, travel and bootstrap.

Prerequisites

Phase 2 health/death/locking and functioning player input.

Future typed dependencies shown on an asset reference page are staged extensions, not a requirement to implement later phases now.

Run the phase tests

Open a shortcut, travel A→B→A, and confirm it remains open. Discover rooms twice without duplicate state. Activate a checkpoint, die, and return to it while model values remain unchanged. Travel with half health and verify no refill. Test missing/duplicate SpawnIds and persistent IDs.

Stop condition

In one running session, area travel and death replace Actors without losing persistent records or carrying stale world references.

Do not move on with an unexplained failure

A checked box should mean you ran the test in your project. Website audit results are not Blueprint test results. Record the actual expected/observed value, current phase, engine build and relevant stable ID/token.

Do not build yet

Disk promises, save-menu polish, complex inventory rules, whole-biome streaming, fast travel.
