Read the relationship, not just the name

BP_PlayerCharacter → PaperZDCharacter (third-party APaperZDCharacter) → Epic APaperCharacter → ACharacter. The Sprite still comes from Paper2D; PaperZD integrates character orchestration.

Indirect inheritance: BP_Enemy_MeleeBasic keeps BP_EnemyBase as its direct parent. APaperZDCharacter is the selected native ancestor through that family, with Epic APaperCharacter beneath it.

Content instances: DA_Equipment_TestHelmet is an instance of the project schema BPDA_EquipmentAppearance, whose native base is UPrimaryDataAsset. ABP_Player is a native PaperZD Animation Blueprint whose generated runtime class derives from UPaperZDAnimInstance. Input actions, textures, sprites, flipbooks, maps and data tables are content assets, not instructions to create Blueprint subclasses.

Project-authored types and engine asset classes

The project names, fields, messages and enumerators remain project-authored, but the assets that store them do have native engine representations: Blueprint Enumerations use UUserDefinedEnum ↗; Blueprint Structures use UUserDefinedStruct ↗; Blueprint Interface assets are represented as UBlueprint ↗ assets with interface semantics related to UInterface ↗.

BPI_Damageable is a project interface, not an Epic IDamageable contract. PaperZD uses UPaperZDAnimInstance for character orchestration; BPC_EquipmentVisuals only projects clothing. The custom ability runtime retains its current gameplay owners. PaperZD is the selected third-party architecture; installed-plugin/build/runtime compatibility remains unverified. See communication and the current asset register.

Blueprint nodes can wrap native helpers, use different display names, or expose different completion mechanisms. Native API links are references, not automatic translations of Blueprint graphs or project functions into C++.

Recognize native naming prefixes

In Epic’s conventions, A marks Actor-derived classes; U is used for other UObject-derived classes; F is common for structs and many non-UObject types; E marks enumerations; and I marks interface types. These are conventions, not a complete classification of every engine type: Actors are also UObjects and other prefixes exist.

The project asset prefixes BP_, BPC_, BPDA_, WBP_, S_ and BPI_ are not interchangeable with native C++ prefixes. Epic C++ naming conventions ↗.
