The central separation

Definitions answer what something is allowed to be. Profile and WorldState own lasting facts. The current body executes temporary gameplay. GameInstance coordinates coherent changes, travel and disk operations. SaveGame is a snapshot. UI and animation observe or request, never own the rules.

Follow a single pickup through all layers

DA_Item_TestReward describes an item. BP_PickupBase shows a world opportunity with a stable PersistentId. Interaction asks it to act; it requests GI.TryClaimWorldReward. Profile gains an owned entry and WorldState gains Collected in one coherent commit. The pickup then hides from its applied record. SaveGame receives copies later. A widget only redraws; it never supplies the missing half of the transaction.

Inheritance is deliberately shallow

Player and enemy bodies both use native PaperCharacter, but there is no shared player/enemy mega-parent. Enemy children share EnemyBase behavior; checkpoint/switch/door/pickup share InteractableBase; test abilities inherit AbilityBase. An NPC implements interaction directly without inheriting hostile AI. Components share behavior without forcing unrelated Actors into the same family.

There is deliberately no universal BP_GameActor or shared player/enemy mega-parent. Stop inheritance at the enemy family, the small interactable family, and the ability executor family. An NPC implements interaction without inheriting hostile AI. A persistent enemy uses a persistence component without inheriting from an interactable. Variations that only change item values or attack tuning belong in definitions, not another Blueprint subclass.

PaperCharacter is a native Character specialization with a flipbook visual component, rather than the usual skeletal-mesh representation. Do not write your baseline animation architecture around a skeletal Mesh component that this class does not set up. [E2]

The layers and their ownership

Definitions are authored, immutable content: item properties, skill costs, attack timings, animation sets, and area destinations. They do not contain the player's inventory quantities, purchased skills, or current health.

Session models contain the current truth about persistent progression. BP_PlayerProfile (Object) owns character progression. BP_WorldState (Object) owns meaningful world changes. BP_GameInstance (GameInstance) constructs them, holds strong references, coordinates cross-model transactions, and writes snapshots. It does not execute attacks or AI.

World framework reconstructs the current map. BP_GameMode (GameModeBase) coordinates area initialization and player spawning. BP_AreaRoot (Actor) describes the current area. Both are replaceable when maps change. Unreal's GameInstance survives ordinary level travel; GameMode does not. [E1]

Bodies and gameplay components implement movement, health, attacks, temporary effects, and active execution. The player and enemies own these Actor Components. Their runtime state can be discarded on death while the session models remain intact.

Presentation reads state and submits requests. BP_PlayerController (PlayerController) owns local UI and input routing. Widget Blueprints derive from UserWidget; they never own inventory, skill rules, or save truth.

The arrows describe requests and information flow, not an obligation to make every object hold every other reference. Profile and WorldState must not call one another. GameInstance coordinates a transaction that touches both. Definitions must not reference live player instances or widgets.

Persistent does not mean immortal Actor. An opened door's record persists; the loaded door Actor can be destroyed and recreated. The same distinction applies to the player body.
