Author cumulative thresholds, not a second XP store

DT_LevelProgression uses S_LevelProgressionRow. Create the row structure first, then the Data Table selecting that exact row type. Use row values for explicit Level ordering; do not assume Data Table row names or returned row-name order already equal progression order.

Process a large award correctly

AwardXP(Amount)
  reject negative/invalid/overflowing award
  OldLevel = derive level from old TotalXP
  NewXP = old TotalXP + Amount
  NewLevel = greatest row with threshold ≤ NewXP
  PointsToGrant = sum(entry awards for OldLevel < row.Level ≤ NewLevel)
  commit XP + derived cache + added points together
  publish progression/build once

Bound traversal by the number of validated rows. Validate unique/consecutive Level values and strictly increasing thresholds under the suggested initial convention. Keep XP at maximum level if following the source baseline, while derived level stays capped. Never let a malformed row cause an unbounded Blueprint loop.

Loading is not another award

Import TotalXP and UnspentSkillPoints, then recompute CachedLevel without running the award loop. A content-version change that moves XP thresholds needs an explicit policy for existing points/builds; do not accidentally refund or re-grant points through cache reconstruction.

The roadmap uses both AwardXP and GrantXP. This guide documents AwardXP as the implementation and GrantXP as a delegating source-name alias. One reward calls one underlying operation. Test a 130-XP initial award with the example table: level 3 and two entry awards; export/import must leave both unchanged.

Canonical roadmap reference · PART Q — Leveling and progression

Current guidance retains gameplay policy and incorporates the PaperZD architecture decision. Historical source text remains in the unchanged original roadmap. E-number references belong to the original roadmap; see verification notes.

BP_PlayerProfile is a Blueprint Class derived from Object. Its Progression category owns TotalXP and UnspentSkillPoints. DT_LevelProgression is a Data Table using the Blueprint Structure S_LevelProgressionRow; neither asset involves selecting a Blueprint parent.

Each row contains Level, TotalXPRequired, CumulativeStatGrowth, and SkillPointsAwardedOnEnteringThisLevel. TotalXP thresholds must be increasing. Level is a derived value/cache: the greatest unlocked row. The save may carry CachedLevel for inspection/migration, but TotalXP plus the versioned progression definition remains the normal calculation source. This is not two competing authoritative values.

GrantXP(Amount) rejects negative awards, captures the previous level, increments TotalXP once, then processes every crossed level and grants the corresponding points exactly once. Bound the traversal by the table's row count. At maximum level, choose and document whether TotalXP continues accumulating; the simple default is to retain it while level remains capped.

Broadcast progression/UI changes after the complete operation, and emit one build-refresh event. On loading, recompute the level without replaying level-up rewards. A balance update that changes thresholds needs an explicit content-version migration, not accidental point grants during import.

Enemies supply an S_Reward value through GameInstance. Profile does not cast to melee enemies, bosses, or pickups. The same reward function can handle any valid progression source.
