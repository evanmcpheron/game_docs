How to use this chapter

Follow the linked phase in order, then open individual asset pages for exact parents, folders, fields, functions and tests. Narrative recipes are suggested implementation details around the preserved architectural ownership rules.

Create a measurable loop before an enemy

Build E_StatId, E_AttackPhase and E_CombatSide, then S_StatBlock, S_StatModifier, S_DamageSpec and S_DamageResult. Compile BFL_GameRules, BPC_Stats and BPC_Health before wiring the target adapter. A dummy with a known 100-health test value is easier to reason about than an enemy that is simultaneously moving, deciding and granting rewards.

  1. Initialize dummy Stats from known values, inject Stats into Health, then enable its BPI_Damageable implementation. Use a direct development call to send a 10-damage packet and inspect the result.
  2. Add Combat to the player with direct references to its ActionState and Stats. Create the two attack definition instances and select grounded/airborne eligibility from native movement state.
  3. On IA_Attack Started, ask the player to request TryStartAttack. Validate first, acquire a token, capture raw damage once and begin execution. A held button should not begin a new swing every frame.
  4. Draw the test hit box and current phase while attacking. Keep damage functional even when there is no attack flipbook.

The active interval can be crossed in one update

With Windup W, Active A and Recovery R, the active interval starts at W and ends at W+A. Keep previous and new elapsed values. A delayed update can cross both boundaries; testing only “current phase equals Active” can miss it entirely.

Previous = ElapsedTime
ElapsedTime += DeltaSeconds
CrossesOrOccupiesActive = ElapsedTime >= W AND Previous < W + A
if CrossesOrOccupiesActive AND this execution still owns its token:
    perform active-entry/query work before deciding that recovery is already over
if ElapsedTime >= W + A + R:
    FinishAttack(ExpectedToken)

This handles time coverage, not perfect continuous collision under arbitrary frame stalls. Sweep the previous/current hit-box positions and validate against thin targets at low frame rates. A test that only prints “Active was entered” does not prove spatial hit coverage.

One attempt per target per swing

Use the initial box or swept-box shape in world X/Z with explicit Y thickness. Mirror the forward X offset by FacingSign. Query suitable object types, normalize hit components to their damageable owner Actor, reject the source/friendly side under the chosen simple policy, and check blocking geometry. Add the Actor to HitTargets before making the interface request so a reentrant callback cannot process it twice.

The roadmap’s simple policy counts even an invulnerability rejection as that swing’s one attempt. Do not keep retrying the same rejected target every active frame unless the design deliberately changes. Clear HitTargets for a newly accepted swing. AttackToken alone is not a globally unique attack ID across different attackers; target deduplication in this architecture is local to each execution.

Acceptance and reactions have different owners

Combat/Projectile/Hazard → BPI_Damageable.ReceiveDamage
Target Actor adapter → Health.TryReceiveDamage
Health → ready/dead/invulnerability validation → Stats.GetStat(Defense)
Health → calculate mitigation once → clamp CurrentHealth → establish lethal guard
Health completed events → body knockback/interruption/death adapter
Enemy legitimate death → guarded GI reward command
Player legitimate death → guarded GameMode recovery request

For the first test, CalculateDamage may use Max(0, RawDamage - Defense). That exact arithmetic is a suggested test implementation, not the final RPG damage model. Put it in BFL_GameRules with explicit arguments so both dummy and player use the same calculation. Raw damage scaling belongs to the source attack; defense is applied once by target Health.

Establish bDead before publishing callbacks from a lethal hit. Body listeners should prioritize a lethal reaction over ordinary Hitstun. A zero-health body cannot be revived accidentally by a late attack finish. Health knows nothing about checkpoint maps, XP rewards or saving, and animation completion is never required for a kill to be legitimate.

Cancellation needs identity, not just a Boolean

Attack A receives token 4. It is interrupted, so ActionState advances to token 5 for Hitstun. A later callback from A carrying 4 must fail to release token 5. On cancel, stop queries/update and invalidate local callbacks. On finish, also verify that the current execution is still the one being finished. “Is attacking” alone cannot identify which attack a timer belongs to.

Add the ranged route in Phase 5

Suggested implementation detail completing an underspecified source hook: add the typed ProjectileClass and ProjectileSpeed fields to the existing attack schema only after BP_ProjectileBase exists. An absent ProjectileClass chooses the initial melee query; a valid assigned class chooses one projectile spawn at active entry. Use a bProjectileSpawned guard on Combat for that execution, clear it on each new attack, and do not perform the melee damage route as well. This adds fields/functions to existing assets, not another attack enum or new folder.

Initialize the projectile’s damage snapshot, source exclusions, owner/instigator and movement before enabling impact handling. Its SphereComponent is the collision root used by native ProjectileMovement. Mark bConsumed before requesting target damage and route overlapping contact callbacks through the same handler. A wall impact consumes it without treating an unsupported Actor as a successful damage target.

Hazards and completion tests

A sustained hazard needs a current-target collection and per-target repeat deadline. On entry, select the initial-attempt convention; while a valid Actor remains inside, attempt only when the deadline is reached. On exit/teardown, remove it. Test that damage frequency is independent of render rate, and that repeated component overlaps do not multiply damage.

Before adding enemy complexity, prove grounded and airborne attacks, deduplication, blocked-wall rejection, invulnerability rejection, lethal once-only detection, cancellation in each phase and a delayed update spanning the entire active interval. A missing flipbook must change none of those results.

Canonical roadmap reference · PART N — Combat architecture

Current guidance retains gameplay policy and incorporates the PaperZD architecture decision. Historical source text remains in the unchanged original roadmap. E-number references belong to the original roadmap; see verification notes.

Start with one grounded attack, one airborne-compatible attack definition, a dummy, and one hazard. Use the exact classes in the phase-2 table: BPC_Combat, BPC_Health, BPC_Stats, and BPC_ActionState are ActorComponent-derived Blueprint Actor Components; BP_TrainingDummy and BP_Hazard are Actor-derived Blueprint Classes; BPI_Damageable is a Blueprint Interface asset.

Execution order

The Controller sends attack intent to the body. Combat verifies health, action permission, grounded/airborne eligibility, and definition validity. It acquires an action token from ActionState, snapshots any stats that should remain constant for that attack, and starts Windup → Active → Recovery. BPDA_AttackDefinition, a Blueprint Class derived from PrimaryDataAsset, provides those timings and the hit-shape/scaling data. Its phase-2 DA_ instances are listed in Part AA.

Use one authoritative elapsed-time calculation in Combat. Enable its update only while an attack is running. Determine whether the interval between the previous and current update intersects the active interval; this prevents a low-frame-rate update from skipping an entire short active window. Query at active-window entry, not only on a later overlap event.

Hit detection and hurtboxes

Keep a consistent gameplay hurtbox independent of the displayed sprite; the Character capsule can serve initially. Define a box/swept box in front of the attacker in XZ, with explicit Y thickness. Follow its previous/current transform during the active window. Query only suitable target object types, filter with BPI_Damageable, and check world obstruction so attacks do not hit through blocking walls unintentionally.

Normalize multiple hit components to one damageable Actor. Track a Set of processed Actor references per attack instance. Decide once whether an invulnerability rejection counts as processed; the recommended simple policy is one damage attempt per target per swing. A new swing gets a fresh set and token.

Damage application

S_DamageSpec and S_DamageResult are Blueprint Structure assets; no parent. The source sends raw damage, source/instigator references, combat side, attack token, and optional knockback. Runtime Actor references are acceptable here because this packet is never serialized into a save.

The target Actor's interface implementation delegates to Health. Health rejects dead/unready/invulnerable targets, obtains the final defensive value from Stats, applies the chosen mitigation calculation once, clamps health, and emits an accepted-hit event. The owning Character performs movement-specific knockback and requests hitstun. Health emits death once when crossing to zero.

Use this one damage pipeline. Do not also call native Apply Damage for the same hit unless you deliberately replace the interface pipeline with a native-damage adapter. Mixing two entry paths is a common double-damage bug.

Interruption, projectiles, and hazards

On interruption, release only the matching action token, stop hit queries, invalidate callbacks from the canceled execution, and notify presentation. Never let a delayed recovery event from attack A unlock the input lock belonging to attack B or death.

BP_ProjectileBase is a Blueprint Class derived from Actor. Add a native SphereComponent collision root and ProjectileMovementComponent; do not create a custom movement-class asset. Set owner/instigator, exclude the shooter, configure swept collision, and guard consumption so a projectile cannot apply the same impact twice. Test fast projectiles against thin geometry.

BP_Hazard (Actor) uses the same damage interface. For a sustained damaging region, maintain a per-target repeat deadline and remove invalid targets; do not apply damage every overlap callback/frame without an explicit repeat policy.

Enemy rewards are emitted by the enemy's once-only death/reward handling, not by the animation and not by the attacker's HUD.

PaperZD presentation timing

PaperZD observes accepted attacks and cancellation; Combat remains the sole Windup/Active/Recovery and hit/release clock. Use sequence notifies for telegraph sound, effects and presentation callbacks. The existing ranged route releases once at authoritative active entry. A notify timing request must validate the current token/body/window and share the release guard with an authoritative deadline fallback; interrupted/missing notifies cannot remove intended active-entry work or unlock/lock actions. Test interruption in every phase with notifies removed.

Resource-free basic combat and later active skills

Phase 2 movement, jumping, grounded and airborne basic attacks remain resource-free even at zero mana/stamina. Add BPC_Resources to the player beside Stats/Health/Combat, not inside Health; bind resource HUD observers after body readiness. No Phase 2 attack-cost fields or optional traversal mechanics are added. Phase 9 authored active skills may cost mana, stamina, both or neither through BPC_Abilities, while retaining Combat's existing action-token arbitration. Only an approved future independent attack-cost requirement may extend AttackDefinition/Combat.
