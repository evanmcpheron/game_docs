NPCs and conditional dialogue

Keep authored lines, current conversation and remembered facts in different places.

How to use this chapter

Follow the linked phase in order, then open individual asset pages for exact parents, folders, fields, functions and tests. Narrative recipes are suggested implementation details around the preserved architectural ownership rules.

Build the smallest condition-sensitive conversation

Create E_ConditionKind, then S_Condition and S_DialogueLine, then S_DialogueVariant. Compile BPDA_DialogueDefinition from PrimaryDataAsset and create DA_Dialogue_TestNPC. BP_NPCBase derives directly from Actor, implements BPI_Interactable and owns a visual plus the authored NPCId/definition. It does not inherit enemy AI.

Use two obvious fixture variants: FirstVisit has higher priority and requires a completion flag to be absent; Repeat is an eligible fallback. Each contains a few development lines. These names/text are test content, not a final cast or story.

Evaluate conditions without side effects

Support exactly MinimumLevel, PurchasedSkill, WorldFlag, ObjectState and Capability. Evaluate against read-only Profile/WorldState values and derived capability tags. All conditions in a variant must pass. Choose highest priority; a suggested stable array-order tie break should be documented and accidental equal-priority ambiguity reported during content validation.

Do not set a seen flag while asking whether a variant is eligible. That would make UI refresh order alter story state. The condition structure is a small explicit vocabulary, not an arbitrary scripting language, quest framework, morality or faction system.

Only authored completion commits memory

NPC.Interact → Controller.BeginDialogue
  validate current player + definition + nonempty eligible variant
  clear gameplay intent; acquire modal policy; pause simulation
  set CurrentLine=0 → show first line
Confirm → validate cursor → advance once
Final authored completion → GI commits CompletionFlags → close modal
Cancel / travel / teardown → close without completion flags

World simulation is paused during modal dialogue under the source baseline. Ensure confirm/cancel still works through the chosen focused input route. When closing, restore input mode/focus and clear cached gameplay intent before unpausing. Loading restores remembered facts, not the exact line that happened to be displayed.

A local PersistentState component is needed on an NPC only when its local presentation projects a saved object record. Global conversation flags do not require another copy on every NPC Actor. Test first visit, repeat, changed level/world conditions, cancellation before final line and reloaded NPC with no UI remaining from the old map.

Animated NPC presentation

The stationary dialogue fixture keeps BP_NPCBase → Actor. Static visuals can remain a PaperSprite/flipbook component. When this NPC is animated, use one native PaperZD Animation component linked to its Sprite and a source-compatible PaperZD AnimBP; author only the required NPC poses in that source. A moving animated NPC may use PaperZDCharacter when CharacterMovement is needed. Do not add an enemy parent/AI or a bespoke playback component. NPCId/interaction stay on the Actor, dialogue cursor stays on Controller, remembered facts stay on WorldState. Notifies may trigger sound/effects; dialogue completion and modal cleanup remain explicit controller operations independent of animation.
