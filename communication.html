Commands request; events report

TryEquip requests a change and returns success/failure. OnEquipmentChanged reports that the authoritative slot map has already changed. A widget may react, but the operation must still be correct when no widget exists. Do not put half of a transaction in an event listener; that makes listener order part of gameplay correctness.

For cross-model commits, validate/stage all values, suppress intermediate notifications, mutate both models, increment one revision and only then publish. Queries can observe the complete new state during publication; nested mutations are rejected. Standalone Profile commits use OnProfileCommitted once, while GI-coordinated commits must not double-count that same operation.

Interfaces are contracts on the receiving Actor

Create an interface asset with named inputs/outputs, then add it in the implementing Blueprint’s Class Settings. Implement its functions on that Actor and delegate to the appropriate owned component. Adding BPC_Health does not by itself make the owning Actor implement BPI_Damageable; wire the adapter explicitly.

Use Does Implement Interface when filtering candidates and validate the target reference. A message to an unsupported or destroyed target cannot be treated as a successful damage, interaction or ability application. The persistent interface has no success output because it is a reconstruction contract; bootstrap must validate the component/identity prerequisites before calling it.

Binding is a lifecycle responsibility

Bind the specific listener once, then pull a current snapshot. On pawn replacement or screen reconstruction, unbind old sources before binding new ones. On EndPlay/teardown, clear long-lived model bindings and old Actor/component references. Avoid broad unbind-all calls that could remove other listeners unintentionally; remove the subscription this owner installed.

Casting is useful at a known boundary

Obtaining the configured GameInstance and casting once to BP_GameInstance is a reasonable framework boundary. A Cast checks whether a reference has the required type; it does not find the object or send an event. Repeated arbitrary casts from HUD through pawn through enemy through inventory are a warning that ownership/injection is unclear, not proof that all casting is bad.

Keep value messages separate from references

S_DamageSpec and S_AbilityContext may contain temporary Actor references because they are current execution packets. S_CharacterSave, S_WorldSave and S_RuntimeTravelState must not contain those references. A stable ID lookup lets an unloaded door be changed; no Cast can make an unloaded door Actor valid.
