Beginner glossary

80 terms explained in the context of this project.

Native C++ names and Blueprint mapping boundaries.

Plain-language meanings specific to this architecture. Click the related page to see the term used in a build/test context.

Action token
A generation identifying which accepted action owns the current lock. Old callbacks must carry and validate their token instead of releasing a newer action. See it in the guide.
Actor
An object that can exist as a placed or spawned participant in a level, usually with a transform and a world lifecycle. Doors, hazards and projectiles use Actor here; persistent inventory does not. See it in the guide.
Actor Component
Reusable behavior attached to an Actor. These BPC_ classes own health, combat or similar logic but no independent transform. Native scene/collision components supply spatial behavior. See it in the guide.
AIController
A controller for non-player decisions. Here it selects target, movement intention and attack requests; the enemy body moves and Combat owns attack timing. See it in the guide.
Array
An ordered collection of values. Dialogue lines and inventory entries use Arrays. Editing a fetched structure copy requires writing the result back to its container. See it in the guide.
Authored definition
Read-only content describing what an item, attack, area or skill is allowed to be. It is separate from mutable player progress. See it in the guide.
Authoritative owner
The one system allowed to decide/store the truth for a state. Caches, UI copies and save snapshots can reflect that truth without becoming independent competing authorities. See it in the guide.
BeginPlay
An Actor world-lifecycle event used for registration/initial setup. It is not a guarantee that every other participant is ready, and it must not replay persistent rewards. See it in the guide.
Blueprint Class
An editable class asset from which an appropriate runtime object/Actor can be created. Choose the exact listed native or project parent; the BP_ prefix alone does not specify it. See it in the guide.
Blueprint Interface
An asset declaring request/query function signatures that unrelated Actor types implement. It stores no world facts and is not a broadcast. See it in the guide.
Build reconstruction
Resolving lasting choices and authored definitions into the current body’s stats, appearance and derived unlocks. It replaces inputs rather than accumulating old bonuses. See it in the guide.
Character
A Pawn specialization with native character movement and collision support. PaperCharacter inherits these facilities; your jump policy does not replace their physics integration. See it in the guide.
CharacterMovementComponent
The inherited native movement component responsible for velocity integration, floor handling, gravity and collision. Player Blueprint supplies input/jump permission policy. See it in the guide.
Class reference
A reference identifying what class to instantiate, such as an ability executor class. It is not an already-created executor or a persistent purchase record. See it in the guide.
Content version
The version of definition/ID/progression interpretation used by saved data. Changing XP thresholds or renaming stable IDs may require a deliberate migration. See it in the guide.
Cook
Preparing selected project content for the target build. The current development slice must include its referenced test maps/art/executors before production exclusions are applied. See it in the guide.
Coyote time
A short permission window after a genuine walk-off. It uses the same single-jump budget as a grounded jump and is not a second airborne jump. See it in the guide.
Custom event
An event entry point you create in an appropriate Event Graph. Event-based orchestration can coordinate later completions without pretending they are synchronous function outputs. See it in the guide.
Custom function
A function you author, with explicit inputs/outputs and a small responsibility. TryPurchaseSkill and BuildSnapshot are project functions, not built-in Unreal nodes. See it in the guide.
Data Asset instance
One authored DA_ object created from a compiled BPDA_ schema. DA_Item_TestHelmet describes a helmet kind; a separate inventory entry identifies the owned copy. See it in the guide.
Data Table
An authored collection of rows using a selected structure. DT_LevelProgression uses S_LevelProgressionRow; order by explicit level values, not assumptions about row-name iteration. See it in the guide.
Development fixture
Obvious temporary content used to prove a rule, such as TestHelmet or TestPulse. It is not automatically approved final gameplay, story or balance. See it in the guide.
Dirty revision
A committed persistent change not yet included in a successfully written revision. Success of an older write cannot clear newer dirty state. See it in the guide.
EndPlay
A world teardown boundary at which Actors/components should clear timers, references and long-lived model bindings. Unloading is not a legitimate enemy death reward event. See it in the guide.
Engine node
A node supplied by Unreal, such as Launch Character or Construct Object from Class. The guide explicitly distinguishes these mechanisms from custom project APIs. See it in the guide.
Enumeration
A small closed list of named choices such as Windup/Active/Recovery. Preserve the listed vocabulary instead of building one giant catch-all state list. See it in the guide.
Event Dispatcher
A named notification that listeners bind to. In this project it normally reports a completed owner change; listeners are not required to finish the underlying transaction. See it in the guide.
Flipbook
A Paper2D animation asset made from sprite frames and durations. PaperZD orchestrates character playback; simple prop loops use Paper2D directly; a flipbook’s finish is cosmetic, not a reward or damage decision. See it in the guide.
GameInstance
The configured session-lifetime object that survives ordinary level travel. This project uses it to retain models and coordinate transactions, recovery and disk I/O, not to run attacks or AI. See it in the guide.
GameMode
The current map’s framework rule/bootstrap owner. BP_GameMode waits for readiness and spawns a body; it is replaced by ordinary map travel and is not permanent progression. See it in the guide.
Gameplay Tag
A project-configured semantic label such as World.State.Opened or a test capability. It is not another Blueprint class or automatically an entire ability framework. See it in the guide.
Guid
A generated unique identifier value. Generate one once for a new owned inventory entry and save it; do not regenerate placed world IDs every BeginPlay. See it in the guide.
Hit deduplication
Counting a normalized target Actor only once for one swing, even if queries hit several components or frames. A new swing receives a new processed-target Set. See it in the guide.
Hurtbox
The collision/query target used for receiving attacks. Here a consistent capsule or box can serve, independently of the sprite’s changing silhouette. See it in the guide.
Idempotent
Repeating the same operation has the same intended result without multiplying effects. Applying an Opened record twice keeps the door open; it does not regrant a reward. See it in the guide.
Jump buffer
A short-lived pending new press that can be consumed when support/permission becomes valid. Expired or interrupted requests must not cause a jump much later. See it in the guide.
Jump cut
A one-time reduction of positive upward velocity after release to create a shorter jump. It preserves horizontal velocity and must handle a release before the pending launch becomes visible. See it in the guide.
Latent operation
Work that does not finish within the immediate synchronous execution, such as a Delay or asynchronous load flow. It cannot split the project’s atomic value commits. See it in the guide.
Level / map asset
A World asset containing area geometry and placed Actors. One area map can contain several room volumes; changing rooms does not automatically load another map. See it in the guide.
Level travel
Opening another ordinary map, replacing its map-lifetime participants. GI retains models; normal travel hands off runtime health/effect/recharge values to the new body. See it in the guide.
Map container
A key-to-value lookup variable, such as Name → world record or equipment slot → EntryId. It is not the same meaning as a level/map asset. See it in the guide.
Migration
An explicit, tested transformation from supported older saved values to current meaning. It is not silently substituting unknown items or replaying normal level-up rewards. See it in the guide.
Object
A non-spatial Unreal object. Profile and WorldState are explicitly constructed Blueprint Objects, retained by GameInstance. They are not spawned Actors and do not get Actor BeginPlay. See it in the guide.
Object reference
A connection to a particular live object or content instance, not the class itself and not a durable cross-map world identity. Validate runtime references after teardown/delayed boundaries. See it in the guide.
Packaged build
A standalone executable/application and prepared content used to test outside the Editor. The manual includes tests to run in it, not an already-built game. See it in the guide.
PaperCharacter
The native Paper2D ancestor of PaperZDCharacter. Player and enemy bodies select PaperZDCharacter. It uses a flipbook visual representation rather than the usual skeletal Mesh setup. See it in the guide.
Parent class
The class whose inherited behavior and fields a child receives. Create a true child from its existing parent rather than duplicating an asset and copying graphs. See it in the guide.
Pawn
A world Actor designed to be controlled. The player body is a Character, which is a Pawn specialization. A Pawn is not the permanent RPG character record in this architecture. See it in the guide.
Persistence
Meaningful values remain available across the chosen lifecycle boundary. The door Actor may disappear while its Opened record stays in WorldState and later in a disk snapshot. See it in the guide.
PIE
Play In Editor, useful for iteration but not proof that maps/assets are cooked or saves work after a complete executable restart. See it in the guide.
Pivot
The local anchor around which a sprite is positioned. Matching body/clothing pivots, scale and timing are required for convincing synchronized equipment layers. See it in the guide.
PlayerController
The local input/possession and UI owner. It routes requests to the current ready body and manages screen focus. Its conversation cursor is transient. See it in the guide.
Possession
Connecting a Controller to the Pawn it controls. Bootstrap initializes a successfully spawned body and then possesses it; two spawn routes can create an accidental extra Pawn. See it in the guide.
PrimaryDataAsset
The chosen base of BPDA_ schema Blueprints for authored content definitions. These definitions remain read-only during play and do not own quantities or purchases. See it in the guide.
Pure query
A read-only operation that returns information without changing ownership or awarding anything. GetSkillAvailability must not deduct points merely because UI asked a question. See it in the guide.
Recovery state
A valid safe spawn and freshly initialized body rebuilt from lasting progress. Disk load and death recovery do not promise to reproduce an exact airborne/combat instant. See it in the guide.
Reentrant mutation
A new write requested synchronously by a listener while another write is publishing or committing. Reject it with a guard so events cannot expose or alter partially committed state. See it in the guide.
Runtime state
Temporary live execution data such as current health, velocity, active attack, effect deadlines or dialogue cursor. Some values hand off through normal travel but are not disk-save truth. See it in the guide.
SaveGame
An Unreal object type used for disk serialization. BP_SaveGame is a fresh snapshot of committed values, not the live Profile model or an exact Actor-world recording. See it in the guide.
Scene Component
A component with a transform that can parent other scene components. EquipmentRoot organizes visual layer transforms without becoming a new gameplay state owner. See it in the guide.
Schema version
The version of saved value layout. It identifies a supported compatibility path; it does not magically repair an old struct that cannot deserialize. See it in the guide.
Set
An unordered collection without duplicate elements. Purchased IDs, discovered locations and processed hit Actors use Sets when order is not the meaning. See it in the guide.
Snapshot
A copy of values captured at a coherent moment/revision. The writing SaveGame snapshot stays unchanged even while newer live model changes occur. See it in the guide.
Soft reference
A reference that identifies an asset without assuming it is already loaded. Resolve/preload it when required and validate that the packaged cook includes it. See it in the guide.
Spawning
Creating a live Actor in a world, such as a player body or projectile. Use Construct Object from Class instead for the non-spatial Profile and WorldState. See it in the guide.
Stable ID
A durable authored key that refers to the same content/object across reloads and supported updates. Labels, array positions and spawn order are not stable identity. See it in the guide.
Strong reference
A retained object reference that keeps a required runtime model reachable in the project’s lifetime design. GI explicitly stores its constructed Profile and WorldState references. See it in the guide.
Structure
A named bundle of typed value fields, such as S_InventoryEntry. It has no Blueprint parent. Its fields determine whether it is safe for saving or only for a runtime message. See it in the guide.
Transaction
This project’s validate-stage-commit-publish convention for a coherent operation. No callback, Delay, asset load or disk I/O occurs between partially completed related mutations. See it in the guide.
Transient
Temporary for the stated runtime lifecycle. In this guide the persistence boundary is implemented by explicit value export/import; a variable label alone does not implement saving. See it in the guide.
Travel handoff
Value-only runtime health/effect/recharge data held temporarily by GI while the old body is suspended and the new one is not yet ready. It is cleared after successful transfer. See it in the guide.
UserWidget
The base class of planned Widget Blueprints. A widget displays current data and requests commands; hiding or destroying it must not delete authoritative gameplay state. See it in the guide.
Windup / Active / Recovery
The Combat-owned phases before, during and after an attack’s damage interval. Animation presents them but does not decide when they begin or apply damage. See it in the guide.
PaperZD
Third-party character animation orchestration over Paper2D flipbooks; gameplay owners remain authoritative. Animation contract.
PaperZDCharacter
PaperZD’s PaperCharacter subclass integrating its inherited Sprite with a native animation component. Player/enemy bases use it; stationary NPCs can compose the component on Actor.
Animation Source
Native PaperZD asset grouping source-compatible sequences. This project uses the Flipbook Animation Source.
PaperZD Animation Sequence
Source-owned animation asset referencing a Paper2D flipbook and its notify timeline; not an engine skeletal AnimSequence.
PaperZD Animation Blueprint / AnimInstance
Authored graph and its UPaperZDAnimInstance runtime; observes gameplay facts to select and play character presentation.
Animation Notify / Notify State
PaperZD timeline event or cosmetic interval. Gameplay damage, deadlines, interruption and cleanup cannot require its delivery.
Equipment visual synchronization
Small project adapter mapping the rendered PaperZD body sequence/time onto compatible clothing layers, with no independent clock or gameplay ownership.
