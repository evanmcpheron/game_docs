Purpose and boundaries

Its job: Select the compiled schema class in Miscellaneous → Data Asset; edit this instance.

Why this exists separately: This is one authored content object using BPDA_EnemyDefinition. Its identity and field values describe content, while the consuming runtime/model class owns mutable results. It is a development fixture, not a final content commitment.

What it must NOT own or do

Do not Spawn Actor from this data instance, use it as an owned inventory entry or change it to record a purchase/current recharge. Do not relocate it from the canonical folder.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/Tests/. Save the asset with the exact name DA_Enemy_RangedTest. The folder already exists; do not move the asset into a different generic folder.
  2. First compile BPDA_EnemyDefinition. Right-click → Miscellaneous → Data Asset → select BPDA_EnemyDefinition in the class picker. Create an instance, not a child Actor Blueprint.
  3. Populate the field table with this instance’s explicitly labeled fixture values. Register its stable ID in the appropriate existing catalog map when the consuming phase needs it. Leave future fields unused until their systems exist; never mutate the instance to record player progress.

EnemyBase explicit setup reads the definition before Stats/Resources/Health/Combat and AI readiness. The catalog supports content validation/reward lookup; AI does not maintain a duplicate attack definition store.

Required for this fixture; missing/mismatched definition or attack suppresses readiness and reports an error instead of enabling half-initialized AI.

Expected verification: Observe initialized values, readable attack, death reward once, ordinary/unique reset behavior and unsupported definition rejection.

Phase 5
DA_Attack_EnemyRangedTest → DA_Enemy_RangedTest
Attacks array

Open DA_Enemy_RangedTest and add DA_Attack_EnemyRangedTest to Attacks. In the attack instance assign ProjectileClass=BP_ProjectileBase and positive ProjectileSpeed.

Enemy AI/body selects this authored candidate and passes it to the shared Combat.TryStartAttack. One Active entry spawns one initialized projectile instead of the melee hit query.

Required for this enemy attack. An empty/missing attack or required ranged class fails validation before an accepted execution; unset projectile class is intentional for melee.

Expected verification: Observe the right windup, one attack/hit or projectile, obstruction handling and interruption.

Instance versus schema versus owned state

This asset uses BPDA_EnemyDefinition. The schema page defines field meanings; this page supplies its concrete proposed content/fixture configuration. Neither this object nor its schema stores the player’s acquired quantity, selected equipment EntryId or current ability cooldown.

Functions and request contracts

No executable gameplay API belongs on this authored content/value asset. Use its field/value editor and the linked consuming system. Schema classes need editable fields, not player-state mutation or world timers.

Events, dispatchers and observers

No additional custom dispatcher is required for this asset’s first version. Use the referenced model/component events or native lifecycle/input/collision events when relevant. Do not invent a global event bus merely to broadcast every local call.

Interfaces and delegation

No required implemented Blueprint Interface beyond an explicitly inherited contract or a future conditional use described in the source. Owned component/model relationships normally use direct typed references, not a new interface for every call.

Common mistakes

Do not Spawn Actor from this data instance, use it as an owned inventory entry or change it to record a purchase/current recharge. Do not relocate it from the canonical folder.

A source-named function is not automatically an engine node. A later-phase typed field does not require moving its schema earlier. If an implementation seems to require a second authoritative store, stop and check ownership and source naming notes before adding another variable or class.

Definition of done

Continue with the Phase 5 checklist and Enemy bodies, decisions and rewards. Canonical identity comes from the original placement index and phase register; detailed contracts/fields labeled suggested are the expansion, not a claim of engine execution.

PaperZD class selection

AnimInstanceClass is a class reference derived from UPaperZDAnimInstance, selecting ABP_EnemyTest. It is not a wearable appearance instance or an engine skeletal UAnimInstance. The body initializes its inherited PaperZD Animation component with that class after definitions/components are ready. Definitions remain read-only; action state and animation runtime state are never stored here.
