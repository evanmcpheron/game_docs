Purpose and boundaries

Its job: A stationary non-hostile NPC needs interaction and sprites, not enemy movement/AI.

Why this exists separately: A stationary non-hostile NPC needs a sprite, interaction contract and authored dialogue reference, not hostile Character Movement or enemy AI inheritance.

What it must NOT own or do

Do not own a permanent conversation cursor or create quests/reputation/factions not present in the brief.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/NPCs/. Save the asset with the exact name BP_NPCBase. The folder already exists; do not move the asset into a different generic folder.
  2. Right-click empty space → Blueprint Class → All Classes if necessary → search Actor. Select that native parent, not a similarly named project class.
  3. Compile the shell, save it, then add current-phase variables/functions and component instances listed below. If a referenced project class does not exist yet, compile both shells before adding cross-references. Add later-phase features only when their phase arrives.

When and where to connect this asset

Stationary interactable Actor. Place in a safe reachable slice location with NPCId, direct DialogueDefinition and query Trigger. Interact requests Controller.BeginDialogue. Do not inherit enemy AI. Optional local persistent projection is separate from global conversation memory; only add PersistentState/interface when that local record is actually required.

Events, dispatchers and observers

No additional custom dispatcher is required for this asset’s first version. Use the referenced model/component events or native lifecycle/input/collision events when relevant. Do not invent a global event bus merely to broadcast every local call.

On reinitialization, remove the old subscription before binding the new source, then pull current values. On EndPlay or widget teardown, remove the exact subscription and clear old world references. The command must remain correct with no presentation listener.

Interfaces and delegation

This Actor implements BPI_Interactable, BPI_PersistentActor. See each contract for inputs/outputs and failure meaning. Persistent participation on EnemyBase/NPCBase is conditional as documented; Door may later implement AbilityTarget only for an actually needed authored receiver, not automatically.

The Actor adapter forwards damage acceptance to its Health component, persistent application to local collision/presentation, interaction to its specific coordinator/model operation, or ability application to a validated world transaction. Implementing an interface never transfers authoritative state into the interface asset.

Animation integration without hostile inheritance

Keep Actor as the stationary dialogue fixture’s base. For animated NPC presentation add one native PaperZDAnimationComponent (UPaperZDAnimationComponent), set its Render Component reference to this Actor’s PaperFlipbookComponent, and set AnimInstanceClass to a PaperZD Animation Blueprint associated with a Flipbook Animation Source. These are native component/configuration choices, not a new custom wrapper asset. The static fixture can leave AnimInstanceClass unset and show static art.

When authored NPC motion requires CharacterMovement, use PaperZDCharacter for that moving character family. Do not reparent interactables or world markers globally. Author only approved NPC presentation states; no talking/emote catalog is committed by this manual. The NPC still requests Controller dialogue; notifies never commit conversation flags or release modal gameplay state.

Test ownerless animation preview, conversation cancel/complete with animation disabled, repeated map load and render-source compatibility. No runtime test was run here.
