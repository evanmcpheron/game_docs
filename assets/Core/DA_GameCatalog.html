Purpose and boundaries

Its job: Select the compiled schema class in Miscellaneous → Data Asset; edit this instance.

Why this exists separately: This is one authored content object using BPDA_GameCatalog. Its identity and field values describe content, while the consuming runtime/model class owns mutable results. Its initial numeric values and test references remain provisional.

What it must NOT own or do

Do not Spawn Actor from this data instance, use it as an owned inventory entry or change it to record a purchase/current recharge. Do not relocate it from the canonical folder.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/Core/. Save the asset with the exact name DA_GameCatalog. The folder already exists; do not move the asset into a different generic folder.
  2. First compile BPDA_GameCatalog. Right-click → Miscellaneous → Data Asset → select BPDA_GameCatalog in the class picker. Create an instance, not a child Actor Blueprint.
  3. Populate the field table with this instance’s explicitly labeled fixture values. Register its stable ID in the appropriate existing catalog map when the consuming phase needs it. Leave future fields unused until their systems exist; never mutate the instance to record player progress.

Phase 5
DT_LevelProgression → DA_GameCatalog
LevelProgression

Create the Data Table with S_LevelProgressionRow; author explicit ordered Level values, cumulative TotalXPRequired/Growth and points-on-entry. Assign DA_GameCatalog.LevelProgression=DT_LevelProgression.

Profile derives level/growth from TotalXP and awards every newly crossed threshold once. Import rebuilds the level cache without replaying awards.

Required from Phase 5; invalid/missing curve blocks progression validation. Do not silently substitute automatic per-level rewards or a second XP store.

Expected verification: With the documented three-row curve, one 130-XP award reaches level 3/two point awards; import retains them unchanged. The initial curve is insufficient for all three Phase 8–9 fixture purchases; follow the explicit Phase 9 curve extension without import-time awards.

Instance versus schema versus owned state

This asset uses BPDA_GameCatalog. The schema page defines field meanings; this page supplies its concrete proposed content/fixture configuration. Neither this object nor its schema stores the player’s acquired quantity, selected equipment EntryId or current ability cooldown.

Only populate maps for schemas available in the current phase. The development area/animation references deliberately point to test fixtures; include them in development packaging until approved production references replace them.

Functions and request contracts

No executable gameplay API belongs on this authored content/value asset. Use its field/value editor and the linked consuming system. Schema classes need editable fields, not player-state mutation or world timers.

Events, dispatchers and observers

No additional custom dispatcher is required for this asset’s first version. Use the referenced model/component events or native lifecycle/input/collision events when relevant. Do not invent a global event bus merely to broadcast every local call.

Interfaces and delegation

No required implemented Blueprint Interface beyond an explicitly inherited contract or a future conditional use described in the source. Owned component/model relationships normally use direct typed references, not a new interface for every call.
