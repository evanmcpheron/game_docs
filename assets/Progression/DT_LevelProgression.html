Purpose and boundaries

Its job: A compact ordered progression curve is easier to audit as rows.

Why this exists separately: A compact table makes cumulative XP thresholds and level growth easy to inspect together. Profile derives level from it; the table does not hold current earned XP.

What it must NOT own or do

Do not assume row-name iteration equals level order, sum cumulative growth rows again, or grant level-entry rewards on load.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/Progression/. Save the asset with the exact name DT_LevelProgression. The folder already exists; do not move the asset into a different generic folder.
  2. Create/save S_LevelProgressionRow first. Right-click → Miscellaneous → Data Table and select exactly that row structure.
  3. Add the clearly labeled example rows below, validate explicit Level ordering/increasing thresholds, then assign the table to DA_GameCatalog in Phase 5. A table row is authored data, not an independently ticking level object.

Common mistakes

Do not assume row-name iteration equals level order, sum cumulative growth rows again, or grant level-entry rewards on load.

A source-named function is not automatically an engine node. A later-phase typed field does not require moving its schema earlier. If an implementation seems to require a second authoritative store, stop and check ownership and source naming notes before adding another variable or class.
