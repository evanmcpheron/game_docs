Purpose and boundaries

Its job: Keys for the initial stat fields; expand only for committed stats.

Why this exists separately: This enum provides a small closed vocabulary for the owning system. Keys for the initial stat fields; expand only for committed stats.

What it must NOT own or do

Do not add speculative mechanics or duplicate unrelated movement, animation, AI and action state into one giant list. Review persistent compatibility before renaming/reordering saved values.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/Combat/. Save the asset with the exact name E_StatId. The folder already exists; do not move the asset into a different generic folder.
  2. Right-click → Blueprints → Enumeration. Add exactly the current values listed below, in source order, and save. No Blueprint parent is selected.
  3. Compile consumers that reference it. Keep the vocabulary small and review saved-data compatibility before changing values used by persistent structures. An enum value is not a new gameplay feature approval.

When and where to connect this asset

Data-only contract. Data-only contract consumed by BPC_Stats.GetStat and S_StatModifier.StatId. Create/compile the type before adding those fields or pins; reopen the listed consumers and connect the complete value. It is not an Actor, component or mutable authority to place in the world. Use the linked phase scenario to exercise this message end to end. Preserve original entries; append MaxMana, MaxStamina, ManaRegenRate, StaminaRegenRate in Phase 2.

Events, dispatchers and observers

No additional custom dispatcher is required for this asset’s first version. Use the referenced model/component events or native lifecycle/input/collision events when relevant. Do not invent a global event bus merely to broadcast every local call.

Interfaces and delegation

No required implemented Blueprint Interface beyond an explicitly inherited contract or a future conditional use described in the source. Owned component/model relationships normally use direct typed references, not a new interface for every call.

Appended resource stat keys

Approved addition, 08 October 2026. Preserve MaxHealth, AttackPower and Defense in their original positions. Append MaxMana, MaxStamina, ManaRegenRate and StaminaRegenRate in that order. The final resource maximums and rates are finite and nonnegative; zero maximum means no capacity. Negative flat/percentage modifiers remain valid inputs, but invalid/nonfinite inputs or arithmetic are rejected before the final cache is replaced. Current mana/stamina are not stats.

Keep one formula: Final = ClampForStat((Base + CumulativeLevelGrowth + SumFlatModifiers) * (1 + SumPercentageModifiers)). For all four resource stats the lower clamp is 0. Preserve the existing clamps for the original three stats. Percentages are additive fractions; 0.10 means ten percent. There is no separate resource modifier schema, modifier stack or class selection.

Open the existing Enumeration asset, use New four times, enter the four names exactly and leave the original three entries unchanged. Reopen every Switch on E_StatId and GetStat selector: wire all four new outputs; do not let an unhandled resource key return AttackPower or an implicit zero. Refresh and compile dependent graphs.

Dependencies and communication

No earlier custom asset type is required beyond native engine/plugin facilities. See the current phase for consumer wiring.

Used by / direct known consumers

BPC_Stats, S_StatModifier.

Communication style

Use direct typed references for owned/injected relationships and read-only definitions; interface messages for unrelated world targets; completed-change dispatchers for observers; GI coordination for cross-model mutations and travel. The API caller column identifies the particular route. These dependencies describe types/configuration and known consumers, not an instruction that every asset must hold a reference to every other one.

Changing a value type can affect all direct consumers shown above and their consumers in turn. The dependency reference explains staged shells, cycles and change-impact tracing.

Common mistakes

Do not add speculative mechanics or duplicate unrelated movement, animation, AI and action state into one giant list. Review persistent compatibility before renaming/reordering saved values.

A source-named function is not automatically an engine node. A later-phase typed field does not require moving its schema earlier. If an implementation seems to require a second authoritative store, stop and check ownership and source naming notes before adding another variable or class.

Definition of done

Continue with the Phase 2 checklist and Stats and build reconstruction. Canonical identity comes from the original placement index and phase register; detailed contracts/fields labeled suggested are the expansion, not a claim of engine execution.
