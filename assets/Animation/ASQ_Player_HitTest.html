Purpose and boundaries

Player Hit presentation sequence; placeholder artwork, no gameplay authority.

Paper2D supplies visual assets. PaperZD owns character playback. Gameplay owners retain all permission, timing, damage, inventory, progression and recovery rules. This asset never supplies required gameplay authority.

Create the asset in the Editor

Open AS_Player and create a native Flipbook Animation Sequence named ASQ_Player_HitTest, stored in Content/Game/Animation/. Assign FB_Player_LandTest in the sequence animation data. Save source and sequence. Do not create an engine skeletal AnimSequence or a Data Asset instance.

Components and composition

Authored sequence asset; it has no Actor components. Its native Flipbook animation data references a Paper2D flipbook compatible with its Animation Source.

When and where to connect this asset

Authored presentation. Author through AS_Player, assign the documented placeholder FB_Player_LandTest, save, and select this sequence in the matching state/transition of ABP_Player. This is visible presentation at its introduction phase, not staged damage timing or final artwork. Missing playback/notifies cannot prevent gameplay cleanup.

Creation phase: Phase 2. World setup · Run-now proof · Which test map to use.

Only the current phase’s connections are active. The full reference/dependency list can include later schema extensions; it is not an instruction to add them early. Suggested properties/graph calls are implementation guidance, not verified existing game fields. Compile/configure the real consumer, save its world fixture, and record the linked scenario’s observed result before marking this asset done.

Functions and request contracts

Play this sequence from the Hit node of the owning PaperZD state machine. For Attack, fit presentation play rate to the accepted action duration where useful; never shorten/extend Combat from the clip length. A missing clip produces a diagnostic/fallback pose and leaves gameplay intact.

Events and observers

Author PaperZD notifies/notify states on this sequence for sound, effects and presentation callbacks when required. Runtime playback dispatches them through the consuming AnimInstance. Preview may lack a live owner. Critical damage, action completion and cleanup remain safe when notifies are missing or interrupted.

Interfaces and delegation

No gameplay interface implementation. The AnimBP selects this source-owned sequence from observed gameplay facts; a wearable appearance may map this sequence identity to a compatible clothing flipbook.

Dependencies and communication

AS_Player, FB_Player_LandTest

The Animation Source defines compatibility; this sequence references a Paper2D flipbook; its AnimBP consumes it. Gameplay does not depend on sequence playback succeeding.

Lifecycle and teardown

Save the sequence, source and referenced flipbook. Validate source compatibility and cooking inclusion. Runtime playback time, action tokens and body subscriptions belong to the live component/AnimInstance or gameplay owners, never this authored asset. Interrupted notify-state cosmetics also require state-exit/teardown cleanup in their live presentation handler.

First working data flow

FB_Player_LandTest → ASQ_Player_HitTest → PaperZD Play Sequence node → rendered body pose

Concrete tests

  • Preview Hit; verify expected loop policy in the AnimBP.
  • Interrupt playback and omit every notify: gameplay timing, cancellation and death handling must remain correct.
  • Validate packaged references and, when clothing is supported, matching frame durations/pivots.

Common mistakes

  • Treating placeholder Land art used for Attack/Hit/Death as production animation.
  • Requiring a completion callback to end an attack or hitstun.
  • Manually seeking/resetting the character Sprite alongside PaperZD.

Definition of done

Sequence/source/flipbook references are saved; loop policy, transitions and interruption behavior are proven with gameplay independent of animation.

These are required project tests, not executed results. No Unreal Editor compile, engine build or runtime test was performed for this documentation change.
