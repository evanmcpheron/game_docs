Purpose and boundaries

Wearable sequence-to-layer-flipbook mapping and layout validation; no body state machine.

Paper2D supplies visual assets. PaperZD owns character playback. Gameplay owners retain all permission, timing, damage, inventory, progression and recovery rules. This asset never supplies required gameplay authority.

Create the asset in the Editor

In Content/Game/Animation/, create Blueprint Class → All Classes → PrimaryDataAsset and name it BPDA_EquipmentAppearance. Add the fields below and compile before creating wearable instances. No graph state machine or playback functions belong here.

Components and composition

Read-only wearable content; no Actor components. BPC_EquipmentVisuals receives this mapping and supplied Head/Body render components from the player body.

Functions and request contracts

Content only. The body adapter resolves Appearance through the equipped item definition and supplies this asset to BPC_EquipmentVisuals. The sequence map describes images for an already chosen pose; it never chooses a state, loops, play rate, duration or gameplay action.

Events and observers

No runtime dispatchers, animation notifies or subscriptions are required on this data asset. Profile publishes completed equipment changes; the body resolves the new mapping and refreshes the cosmetic adapter.

Interfaces and delegation

No gameplay interface implementation. Item definitions reference this appearance schema/instance; the body supplies the resolved appearance to BPC_EquipmentVisuals. This mapping never queries or mutates inventory.

Dependencies and communication

AS_Player

Item definition → read-only wearable appearance → body adapter → clothing synchronization. Sequence identities are mapping keys, not a second state selector. Inventory and equipment ownership do not depend on rendering.

Lifecycle and teardown

Save/validate referenced native sequences and layer flipbooks before assigning the appearance to an item. Load required mapping assets before rendering; absent or incompatible entries hide deterministically. Live render references and cleanup belong to the body/adapter. Persist ItemId/EntryId and slot ownership through existing Profile rules, never an animation frame or appearance runtime state.

First working data flow

Profile slot EntryId → Item definition.Appearance → wearable sequence mapping → BPC_EquipmentVisuals

Concrete tests

  • Missing/null sequence mapping hides the layer without changing body playback.
  • Static helmet aligns in both facing directions; unsupported poses hide.
  • Before using animated wardrobe art, compare frame counts, individual frame durations, pivot, scale and mirroring with the body.

Common mistakes

  • Keeping a second state-to-flipbook body catalog here.
  • Treating FrameLayoutId equality alone as compatibility proof.
  • Claiming a static helmet verifies animated clothing for every pose.

Definition of done

Read-only wearable mapping is referenced by the item, validates supported poses and hides unsupported poses; no playback authority remains in the schema.

These are required project tests, not executed results. No Unreal Editor compile, engine build or runtime test was performed for this documentation change.
