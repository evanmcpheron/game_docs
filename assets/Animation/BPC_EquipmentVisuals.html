Purpose and boundaries

Synchronizes supplied clothing components to the body pose rendered by PaperZD; no independent clock.

Paper2D supplies visual assets. PaperZD owns character playback. Gameplay owners retain all permission, timing, damage, inventory, progression and recovery rules. This asset never supplies required gameplay authority.

Create the asset in the Editor

In Content/Game/Animation/, create an ActorComponent Blueprint named BPC_EquipmentVisuals. Add one instance to BP_PlayerCharacter in Phase 7. Disable its autonomous Tick. Supply body Sprite and Head/Body layer references plus resolved appearance assets through InitializeLayers. Do not attach another PaperZD state machine to each wearable.

Components and composition

The owning player supplies its inherited Sprite plus EquipmentRoot, HeadLayer and BodyLayer. This component needs no transform.

EquipmentVisuals

Add BPC_EquipmentVisuals as EquipmentVisuals plus native EquipmentRoot, HeadLayer and BodyLayer; disable wearable collision/autoplay and independent component Tick. InitializeLayers receives inherited Sprite and the slot-to-layer references.

Body build refresh calls SetAppearance from Profile-derived equipment definitions. ABP_Player samples actual rendered sequence/body playback position at its documented presentation callback and calls SyncToBodyPose. Missing sequence mappings hide; ClearLayers clears references on teardown. This adapter never changes the body Sprite or decides equipment/stat rules.

Optional for gameplay correctness, required for supported visible-equipment acceptance. Missing/incompatible appearance deterministically hides its layer and reports the mapping issue; valid ownership/stats still work.

Expected verification: Two facings, immediate airborne equip, pause/restart and no one-frame lag at 30/60/120; unsupported Land/Attack/Hit/Death intentionally hide.

Only the current phase’s connections are active. The full reference/dependency list can include later schema extensions; it is not an instruction to add them early. Functions and request contracts

Suggested custom functions: InitializeLayers(Body, Layers) validates references and stops autonomous layer playback. SetAppearance(Slot, Appearance) replaces the resolved mapping and synchronizes immediately to the last valid rendered body pose. SyncToBodyPose(Sequence, BodyTimeSeconds) resolves each layer clip from that sequence, changes only the layer asset if needed, then sets its playback position with events disabled. ClearLayers hides/stops supplied layers and releases references. None writes the body Sprite, AnimBP state or gameplay owners.

Events and observers

No independent state-change bus is required. The body forwards resolved equipment changes and ABP_Player supplies the post-animation pose observation. Clothing playback is stopped and seeking disables events, so layers do not emit duplicate notifies.

Interfaces and delegation

No gameplay interface or direct Health/Combat/ActionState subscriptions. The body injects render components and resolved wearable mappings; the AnimInstance supplies its already rendered sequence/time. The adapter never selects actions or owns Profile slot entries.

Dependencies and communication

BPDA_EquipmentAppearance, E_EquipmentSlot, ABP_Player

Body → supplied layer refs and resolved appearance; AnimInstance → rendered pose/time → adapter → clothing. The adapter writes only clothing components. No gameplay owner needs it to run.

Lifecycle and teardown

Initialize only after supplied render references are valid; stop autonomous layer playback and keep Tick disabled. Clear/hide layers and release body, appearance and cached-pose references on teardown or owner replacement. Reinitialize for a new body/AnimInstance and source; do not retain subscriptions or a pose from the previous body. Rebuild from equipped entries after travel/load, never saved frames.

First working data flow

ABP_Player.OnTick is a documented post-animation observation point in the referenced plugin source. Read AnimInstance.GetPlayer().GetCurrentAnimSequence() and Sprite.GetPlaybackPosition(), then synchronize layers. Copy the body’s actual visual facing/mirroring while retaining authored layer depth. Equip refresh uses the last rendered pose immediately and the next post-animation callback applies any new pose. Confirm callback order in the installed plugin; a native ordered update can be used if that version differs. Do not add a second playback loop.

Concrete tests

  • Equip during Move/Rise/Fall/Land/Attack/Hit/Death, pause, facing reversal and same-sequence restart; supported layers match body pose/time and unsupported ones hide.
  • At 30/60/120 FPS verify no one-frame lag; replacing the AnimInstance/source rebinds observers and rebuilds layer mapping.
  • Unequip, travel, disk recovery and EndPlay leave no stale visible layer or subscription.
  • Disable this adapter and prove stats, inventory, damage and movement still work.

Common mistakes

  • Accumulating a shared clock in this adapter instead of reading PaperZD’s rendered pose.
  • Calling SetFlipbook/PlayFromStart/SetPlaybackPosition on the body.
  • Letting clothing play autonomously or execute duplicate sound/damage notifies.
  • Binding only a sequence-change event and failing to track time within the same sequence.

Definition of done

The optional adapter copies body presentation to compatible clothing in the same frame, handles missing assets/teardown, and owns no state selection or gameplay.

These are required project tests, not executed results. No Unreal Editor compile, engine build or runtime test was performed for this documentation change.
