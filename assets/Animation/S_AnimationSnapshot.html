Purpose and boundaries

Its job: Velocity, grounded status, facing, action state, action timing; cosmetic input.

Why this exists separately: Velocity, grounded status, facing, action state, action timing; cosmetic input. A named structure lets callers exchange a known value shape without inventing another manager or coupling to a live Actor.

What it must NOT own or do

Do not treat a copied value as a second independent owner. Do not serialize runtime Actor references just because they fit in a structure. Follow the specific saved/runtime boundary in its fields.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/Animation/. Save the asset with the exact name S_AnimationSnapshot. The folder already exists; do not move the asset into a different generic folder.
  2. Right-click → Blueprints → Structure. Add the listed members, select each type/container, set appropriate authored defaults and save. No Blueprint parent is selected.
  3. Create referenced enums/leaf structures first. Refresh/recompile dependent Blueprint pins after a shape change and test old saves before releasing schema changes. To edit a struct stored in a Map/Array, get a local value, change it and write it back.

Value ownership and serialization boundary

Constructed/read by: BP_PlayerCharacter / EnemyBase constructs; animator reads.

Actor references: Not required or permitted by this proposed value schema. Keep the shape free of live world/component/widget pointers.

Save policy: Not exported as permanent disk truth in this roadmap. Even a value-only shape may be intentionally runtime/authored-only. Travel handoff values freeze remaining time but are not exact-instant disk saves.

Functions and request contracts

No executable gameplay API belongs on this authored content/value asset. Use its field/value editor and the linked consuming system. Schema classes need editable fields, not player-state mutation or world timers.

Events, dispatchers and observers

No additional custom dispatcher is required for this asset’s first version. Use the referenced model/component events or native lifecycle/input/collision events when relevant. Do not invent a global event bus merely to broadcast every local call.

Interfaces and delegation

No required implemented Blueprint Interface beyond an explicitly inherited contract or a future conditional use described in the source. Owned component/model relationships normally use direct typed references, not a new interface for every call.

Common mistakes

Do not treat a copied value as a second independent owner. Do not serialize runtime Actor references just because they fit in a structure. Follow the specific saved/runtime boundary in its fields.

A source-named function is not automatically an engine node. A later-phase typed field does not require moving its schema earlier. If an implementation seems to require a second authoritative store, stop and check ownership and source naming notes before adding another variable or class.
