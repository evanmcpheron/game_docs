Purpose and boundaries

Shared development source for the two test enemy families; replace fixture art when authored.

Paper2D supplies visual assets. PaperZD owns character playback. Gameplay owners retain all permission, timing, damage, inventory, progression and recovery rules. This asset never supplies required gameplay authority.

Create the asset in the Editor

Enable Paper2D and PaperZD first. In Content/Game/Animation/, use the PaperZD / PaperZetaD Animation Source creation action and select the native Flipbook source. Name it AS_EnemyTest. Open it and create its named sequences through the source editor; save all related packages. Do not derive a custom source class.

Components and composition

Authored source asset; it owns no Actor components or live gameplay state. Its native Flipbook source type supplies compatibility with a PaperFlipbookComponent render target.

Functions and request contracts

The native source groups sequence authoring and render compatibility. It does not select gameplay actions or calculate time budgets.

Events and observers

The source editor supports sequence/notify authoring. The source asset is not a runtime event listener; its consuming AnimInstance handles presentation events. No source event grants gameplay permission.

Interfaces and delegation

No gameplay interface implementation. Associate native sequences and AnimBPs with this source; the character supplies the native animation component and render target.

Dependencies and communication

Paper2D and PaperZD plugins; no project asset prerequisite.

This source supplies authoring compatibility to its sequences and consuming AnimBP. It does not query gameplay owners or determine action success.

Lifecycle and teardown

Save the source and its related sequence/AnimBP packages after authoring. Keep their source association valid when moving or replacing content and include referenced assets in cooking. Runtime AnimInstances are created by the character animation component; the source stores no body reference, timer, subscription or saved runtime state.

First working data flow

Sprite → Paper2D Flipbook → source-owned PaperZD sequence → AnimBP → Sprite render

Concrete tests

  • Open every associated sequence and preview its assigned flipbook.
  • Compile the consuming Animation Blueprint and verify source compatibility and packaged asset inclusion.

Common mistakes

  • Creating a PrimaryDataAsset wrapper instead of a native Animation Source.
  • Saving only the Blueprint while leaving its sequences/source unsaved.

Definition of done

Native Flipbook source and current-phase sequences are saved, assigned to the intended AnimBP and validated in the installed plugin.

These are required project tests, not executed results. No Unreal Editor compile, engine build or runtime test was performed for this documentation change.
