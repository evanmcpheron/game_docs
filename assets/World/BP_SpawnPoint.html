Purpose and boundaries

Its job: A tagged player-start position fits controlled spawning.

Why this exists separately: PlayerStart already represents an authored spawn transform. This shallow extension adds a stable SpawnId and facing without inventing another spawn Actor framework.

What it must NOT own or do

Do not store player progress or generate the recovery destination from a live character transform. No custom Tick is needed.

Create the asset in the Editor

  1. In the Content Browser, navigate to Content/Game/World/. Save the asset with the exact name BP_SpawnPoint. The folder already exists; do not move the asset into a different generic folder.
  2. Right-click empty space → Blueprint Class → All Classes if necessary → search PlayerStart. Select that native parent, not a similarly named project class.
  3. Compile the shell, save it, then add current-phase variables/functions and component instances listed below. If a referenced project class does not exist yet, compile both shells before adding cross-references. Add later-phase features only when their phase arrives.

When and where to connect this asset

Authored safe destination. Place in registered slices with area-local unique SpawnId and facing on supported clear floor, outside hazards and arrival/reverse transition overlap. GameMode validates/registers it before spawning one player; actor labels are not stable destination IDs.

Functions and request contracts

No additional custom runtime function is necessary for the first version. GameMode collects the placed PlayerStart-derived instances and reads SpawnId, facing and transform. Do not add Tick or a second spawn manager.

Events, dispatchers and observers

No additional custom dispatcher is required for this asset’s first version. Use the referenced model/component events or native lifecycle/input/collision events when relevant. Do not invent a global event bus merely to broadcast every local call.

On reinitialization, remove the old subscription before binding the new source, then pull current values. On EndPlay or widget teardown, remove the exact subscription and clear old world references. The command must remain correct with no presentation listener.

Interfaces and delegation

No required implemented Blueprint Interface beyond an explicitly inherited contract or a future conditional use described in the source. Owned component/model relationships normally use direct typed references, not a new interface for every call.

Common mistakes
